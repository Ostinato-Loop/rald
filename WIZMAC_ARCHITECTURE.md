**Permanent Knowledge Graph and Institutional Memory**
Version: 1.0.0

## 1. CORE MANDATE

> **WIZMAC is the ONLY system allowed to permanently remember things.**

No other system, agent, or service in the RALD Ecosystem may store permanent memories outside of WIZMAC. Temporary session state is permitted in application services, but all permanent knowledge flows through WIZMAC.

---

## 2. PURPOSE

WIZMAC stores and preserves:

- Product history
- Company history
- Cultural knowledge
- Language knowledge
- Voice knowledge
- Institutional memory
- BBC specifications
- Decision logs
- Agent memory
- Origin records
- Incident records
- Migration history

**WIZMAC must function as institutional memory for the next century.**

## 4. ORIGIN RECORDS

Origin Records are a permanent historical system.

**Origin Records record:**
- Why products were created
- Major architectural decisions
- Milestones
- Contributors
- Technologies used
- Lessons learned

**Rules:**
- Origin Records are NEVER deleted
- Origin Records are versioned
- Every product must have an Origin Record
- Every major architectural decision must have an Origin Record

---

## 5. MEMORY HIERARCHY

```
PERMANENT MEMORY (WIZMAC only)
  ├── Origin Records (never deleted, never overwritten — versioned only)
  ├── Decisions (append-only, superseded by new decisions)
  ├── Events (immutable log)
  └── Agent Memory (isPermanent=true — cannot be deleted via API)

SESSION MEMORY (ephemeral, per-session)
  └── Agent Memory (isPermanent=false, with optional TTL)

TEMPORARY STATE (application-level, not WIZMAC)
  └── In-memory caches, request state, connection pools
```

## 7. GOVERNANCE RULES

1. **WIZMAC is the single source of truth for all institutional knowledge**
2. **No permanent memory may be stored outside WIZMAC**
3. **Origin Records are immutable — they can be versioned but never deleted**
4. **Decisions are append-only — a new decision supersedes an old one**
5. **All agent memory routes through WIZMAC**
6. **WIZMAC has admin authority over all other systems' memory**

## 8. INTEGRATION WITH BBC AND SEKANI

```
User Request
  → BBC (parse meaning + intent)
  → SEKANI (route to correct agent)
  → Agent executes
  → WIZMAC (stores result permanently)
  → Response to user
```

WIZMAC is the last step of every BBC-compliant interaction.
